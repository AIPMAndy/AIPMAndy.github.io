CH.01
PART 01 / FIRST PRINCIPLES

先搞懂豆包工作

它不是“豆包聊天加长版”，而是围绕结果调度研究、文件、工具和团队上下文的工作 Agent。

直接照做：操作路径
  1. 先写最终成果，而不是提一个模糊问题
  2. 确定它可读取哪些素材、能动哪些系统
  3. 让 AI 先列出计划与风险，再开始执行
  4. 拿到文件后独立验收

三个经常混淆的名字

豆包是通用 AI 助手；豆包中的“工作任务”是其中的任务入口；豆包工作是以交付任务为核心的产品形态，并与飞书深度集成。不要把普通对话的能力、企业权限和本地电脑操作视为完全相同。

什么任务值得交给 Agent

优先选择“输入明确、可检查、重复发生”的任务，例如把会议纪要转成行动表、从真实样本建立报告、整理有备份的临时文件夹。像“替公司做最终法律判断”这种缺乏可授权和可验收边界的任务不宜委托。

一个正确的工作流

任务=目标 → 材料 → 计划 → 执行 → 可编辑交付物 → 人工验收。把一次成功操作记录下来，逐步形成稳定流程。工具是否会升级并不改变这个逻辑。

产品不是承诺

官方描述中包括浏览器/电脑操作、图表、演示、视频和技能等，但每个入口、账号、订阅权益和企业管理配置的支持范围不同。无法在你的界面看到的功能，按不可用处理，不要靠文字假定已经开通。

✓ 完成标准
  • 解释清楚普通豆包和豆包工作的差异
  • 选出一件 15 分钟内可复核的小任务
  • 知道为什么最终成果必须检查
! 常见风险
  • 把普通聊天结果当成完成工作
  • 相信没有来源的统计数字

下载、入口与账号

认准官方入口，再决定个人还是飞书企业身份；这是数据边界，不是换个登录按钮。

直接照做：操作路径
  1. 打开 https://www.doubao.com/work
  2. 下载与你系统匹配的官方客户端；无法安装则确认豆包现有工作入口
  3. 用个人账号完成无敏感数据测试
  4. 使用飞书企业账号前先确认租户及授权范围

先辨别入口

独立 PC 客户端适合较长任务和本地操作；豆包客户端内的工作入口适合从熟悉的环境进入；飞书端适合企业知识与协作。独立“豆包工作”目前并非独立手机版 App，手机相关工作通过豆包或飞书入口承接。

个人账号不是企业账号

个人豆包身份对应个人空间；飞书身份对应企业租户、已有文档权限和管理员控制。同一个手机号不代表这两套空间的资料、额度或任务自动合并。切换身份前先确认头像/租户/目标文件空间。

安全安装

只从 doubao.com 或相关官方应用商店的核验渠道获取程序，不安装镜像站宣传的“免登录破解版”“加速版”。软件索要本地文件、辅助功能或录屏权限时，先确认具体任务确实需要。

在电脑建“豆包工作-练习区”，只放我们提供的模拟会议纪要和模拟销售数据。不使用客户名单、真实简历、公司机密或私有密钥测试。

10 分钟完成第一份交付物

从模拟会议纪要开始：一条指令，交付负责人明确的行动表。

直接照做：操作路径
  1. 打开 examples/meeting-demo.md 并复制为本地文件
  2. 进入豆包工作，选择可处理本地文件的入口
  3. 发送本章任务指令，先观察计划
  4. 生成行动表后对照原文逐项检查
  5. 保存输出为可编辑的 Markdown/表格

复制这条初始任务

请读取我提供的模拟会议纪要。输出 Markdown 行动表，字段为任务、负责人、截止日期、证据原句、风险。原文没有的日期标记“待确认”；不推断负责人，不联系任何人，不修改原始文件。先列 3 步计划再执行。

检查质量

核查行动项个数、负责人、日期与证据原句是否一一对应；有歧义一律标明。格式与事实同样重要，但不要为了表格看着完整去编空缺。

迭代一轮

再要求“只补充一个按优先级排序的风险提示段落，不能改动已确认的行动项；单独给出你修改了哪里”。让读者感受局部纠偏，而不是每轮整篇重做。

留存复现材料

把输入、最终提示词、输出和人工验收清单放在同一目录，命名为 YYYY-MM-DD-meeting-demo。后续才有条件验证是不是稳定省时间。

  • 行动项有出处
  • 未知事项明确标注
  • 原文件没有被修改
  • 能复现最终输出
! 常见风险
  • 编造确认日期
  • 未经许可向群聊发送通知
CH.04
PART 02 / PROMPT ENGINEERING

任务委托八字段协议

把“帮我做一个报告”升级为带验证标准的任务委托书。

直接照做：操作路径
  1. 明确目标与接收对象
  2. 填写输入材料及来源边界
  3. 给出分步骤执行策略
  4. 写清输出文件格式与命名
  5. 写出成功标准和必须停下的条件

八个字段

①任务目标；②交付对象；③可用输入；④范围/时效；⑤执行约束；⑥输出格式；⑦验收标准；⑧需人工确认的动作。缺两项以上，先让它提不超过三个关键问题。

先计划，再执行

复杂任务可先让 Agent 交一页路线图：需要哪些材料、哪些步骤并行、哪些步骤依赖外部授权、哪些环节人来确认。这样花费更可控、错误更早暴露。

五步法过滤无效工作

先质疑任务是否必要，再删除不创造结果的步骤，然后简化，随后提速，最后才考虑自动化。自动化一个错误流程只会更快地产生更多错误。

交付文件必须可编辑

不要只交图片、截图或“完成了”的说明。约定生成 Markdown/CSV/PPTX/HTML 等可编辑格式，并在清单上写文件路径、生成时间、所用来源及遗漏项目。

✓ 完成标准
  • 协议中有八字段
  • 授权与停机条件明确
  • 可以观察任务状态
  • 输出有验收指标
! 常见风险
  • 用“你自己看着办”取代边界
  • 没有备份就授权批量改写
CH.05
PART 02 / CONTENT DELIVERY

高质量文档、报告与 PPT

先保证证据，再保证表达，最后打磨视觉：这是办公成果最短的可信路径。

直接照做：操作路径
  1. 上传或指定已授权材料
  2. 提取事实与待核实清单
  3. 确认大纲和受众
  4. 生成文档和汇报版 PPT
  5. 逐页检查引用、图表和排版

一套材料两种受众

同样的项目复盘，团队版应写清任务、Owner 和阻塞；高管版优先讲关键指标、风险、需要决策的事项。不要无区别复制同一个 PDF。

写作不是幻觉大赛

任何收入、行业规模、政策、用户数都应附原始来源或明确注明“估算/教学模拟”。不能用 AI 自己编造的数据支持下一步建议。

局部修改优先

对于已经合格的初稿，指定章节/页面/段落修改，要求列出变更摘要，不重写其他部分。必要时保留 v1、v2 以便回滚。

PPT 交付验收

至少检查每页唯一中心信息、数据与正文一致、图片版权或授权、中文字体替换、可编辑性、边距与手机阅读。PPTX 可以打开 ≠ 演示材料可交付。

✓ 完成标准
  • 结论可追溯
  • 有决策摘要
  • PPTX 有可编辑元素
  • 不对外传播敏感资料
! 常见风险
  • 把模拟指标写成真实业绩
  • 只验“文件能打开”

PART 02 / DATA

表格、数据分析和可视化

模型会画图，不代表它理解数据口径；先验数，再画图。

直接照做：操作路径
  1. 用 examples/sales-demo.csv 导入模拟记录
  2. 先检查字段、重复、缺失和日期格式
  3. 要求计算订单金额和分组汇总
  4. 核对至少三个手算样例
  5. 生成图表并在结论旁写明限制

分析四道闸

数据来源可靠性 → 统计口径 → 计算复核 → 结论边界。比如“成交率”分母究竟是咨询数、有效线索数还是访客数？一个分母没说清，后续图表全不可信。

对异常要追因

发现某个月收入升高，只能说“指标变化”，不能直接归因为“AI 带来了增长”。要进一步检验样本、活动、渠道和季节性因素，必要时做对照实验。

模拟数据的使用规则

本项目提供的所有 CSV 均为人为构造的教学数据，不代表 AI 酋长 Andy 的客户、订单或成交事实。案例展示时必须保留“教学模拟”标签。

可复现与导出

保留源 CSV、字段字典、计算式、最终图表和一段文字解释。实际企业可把模板改写为受控的飞书多维表格或 Excel 流程。

✓ 完成标准
  • 源数据不被覆盖
  • 总金额可手动核对
  • 图表标题带单位
  • 结论不越过因果边界
! 常见风险
  • 在没有字段字典时比较转化率
  • 将演示图用于真实客户宣传
CH.07
PART 02 / RESEARCH

深度研究与来源核验

让 AI 承担资料搜索和结构化汇总，人负责判断来源、时效和因果。

直接照做：操作路径
  1. 限定问题、地域与日期
  2. 优先官方公告、产品文档和原始报告
  3. 每个关键结论旁保留可点击来源
  4. 对冲突信息单独列出
  5. 输出事实、判断与未知三栏

证据等级

第一级：原始官方公告/财报/政策；第二级：有署名与方法的专业媒体；第三级：社区经验；第四级：无法核实的转述。低等级证据可以作为线索，不可伪装为确定事实。

发布日期与事件日期分开

一条新闻可能 11 月发布，却在说 8 月的产品更新。分析最新能力时写明“核验日”而不是只写文章发布日期。

研究应服务决策

报告至少回答“什么变了”“为什么重要”“怎么验证”“下一步最小动作”。如果只得到一堆截图与长文本，没有形成可行动判断，就不算完成任务。

引用检查

随机抽查 5 个主要结论，打开原链接查数字与上下文，遇到来源打不开就暂时删除该结论。不要让模型凭记忆补上链接。

✓ 完成标准
  • 所有核心事实有来源
  • 时效边界清楚
  • 存在反例/不确定项
  • 给出最小可验证行动
! 常见风险
  • 使用凭空生成的链接
  • 把产品宣传语当第三方测评
CH.08
PART 03 / EXECUTION

本地文件整理与批处理

安全的文件自动化应先预演、再确认、再执行、可回退。

直接照做：操作路径
  1. 备份练习目录
  2. 只读统计数量、格式、大小
  3. 生成 dry-run 重命名预览
  4. 检查文件冲突和重名处理
  5. 批准后在练习区执行
  6. 输出变更日志并复核

文件夹白名单

明确只操作“练习区”的绝对路径，不包含桌面根目录、下载全目录、云同步库或企业共享盘。先限制范围，再给权限。

dry-run 是必需品

让 Agent 在真正写盘前生成旧路径→新路径清单和可能覆盖项，默认禁止删除；如果产品没有预演按钮，就让它先只读输出变更计划。

回滚方法

执行前复制备份，执行后保存旧名/新名映射；失败时按映射回退。对 50 个文件不可靠的流程，不要直接上 50,000 个文件。

不要过度授权

屏幕录制、辅助功能、磁盘访问、管理员权限是不同级别的授权；按任务最小范围开通，不需要时及时撤回。

✓ 完成标准
  • 先查看预演
  • 无人为遗失文件
  • 有可执行回滚方案
  • 输出目录有日志
! 常见风险
  • 全盘批量移动
  • 临时文件中包含个人密钥

PART 03 / EXECUTION

浏览器操作与电脑接管

多步骤 GUI 操作很有价值，也最容易误操作：把高风险动作设为人工审批点。

直接照做：操作路径
  1. 选择公开可访问的测试页面
  2. 给出允许访问的站点列表
  3. 先让它只读检索并截图/整理证据
  4. 发送/删除/付款/发布前要求暂停
  5. 检查操作日志与目标页面

什么可以自动

公开页面提取、自己的素材整理、测试站点录入、已授权文档编辑；但不保证每个系统都支持自动化，验证码、反机器人机制和管理员策略都不能绕过。

什么必须人工

向客户发送消息、对外发布内容、移动资金、提交合同、覆盖正式数据、删除仓库，以及任何改变外部系统权限的动作，都必须先确认目标、对象和内容。

云电脑和本地电脑不是一回事

云端任务有机会在关机后继续运行，但本机 GUI 操作往往依赖设备可用、权限与在线状态。不要把“云任务可继续”理解成“关机后还可随意操作本地软件”。

何时停止

页面与预期不同、出现额外授权窗、目标账号不一致、找不到原始凭证、页面显示限流/失败时立即暂停并汇报，不继续猜测点击。

✓ 完成标准
  • 只在白名单站点操作
  • 保留关键截图或变更记录
  • 高风险操作前暂停
  • 有失败退出条件
! 常见风险
  • 绕过验证码/反爬
  • 未经授权触达第三方

PART 03 / FEISHU

飞书企业知识与协作

真正的差异化不是聊天速度，而是企业上下文能否进入正确工作流。

直接照做：操作路径
  1. 以自己的飞书企业账号登录
  2. 确认当前租户和授权资料
  3. 选一份可公开于团队的练习文档
  4. 让它汇总行动项并引用原文
  5. 生成可编辑成果后复核分享范围

企业权限继承

豆包工作与飞书打通，不意味着能读取整个企业的数据。你能访问什么、是否允许调用相关工具、是否允许分享给谁，继续受飞书权限与管理员开关约束。

最适合的企业内用法

结合自己有权限的会议记录、项目文档和日历，做周报、项目风险跟踪、客户拜访准备、知识问答。跨部门数据汇总先找数据所有者确认。

共享后的二次风险

一份由 AI 生成的文档可能包含原始文件的敏感段落，创建文档前/分享前都要审阅权限、敏感词、客户名与保密约定。

最小闭环

选一份会议记录→提取行动表→让负责人确认→存回被授权的团队目录。只有当“任务被使用且正确”才计算流程有效。

✓ 完成标准
  • 确认组织/租户
  • 保留引用原文
  • 对外分享前再审
  • 不会绕过资料权限
! 常见风险
  • 直接让 AI 遍历企业全盘
  • 自动群发未经审查的周报

PART 03 / EXTENSIBILITY

技能、连接器、工作伙伴

记住：技能是方法，连接器是通道，工作伙伴是负责执行的角色。

直接照做：操作路径
  1. 先找到已有技能解决的明确问题
  2. 检查技能来源、访问范围与脚本内容
  3. 按最小权限安装连接器
  4. 给伙伴限定角色和验收标准
  5. 先在模拟数据上运行

技能 Skill

标准化流程、验收规则、可选脚本、资源模板组成一个技能。技能不是只写一句 Prompt。自定义技能需遵从产品当前上传结构与审核规则，本仓库提供一个平台中立的 Markdown 示例，不保证直接一键导入。

连接器 Connector

它把外部账号、文档或系统接入任务。授权前明确“接谁的数据”“能否写入”“什么时候撤销”“输出落在哪里”。连上服务并不自动意味着可以读取所有数据。

工作伙伴 Partner

伙伴是任务中的专业角色，可以组织为小队处理研究、数据、设计等分工；每个伙伴都应有职责、输入、产出、质量门槛。多人并行也可能放大一致性问题。

审计第三方能力

对要求安装的本地代码先阅读文件清单，拒绝索要 Token/密码的示例，不执行来源不明的网络脚本或带 sudo 的安装指令。

✓ 完成标准
  • 职责边界可解释
  • 权限可撤销
  • 第三方脚本过审
  • 技能输出可复验
! 常见风险
  • 信任不明技能自动读写
  • 把 API Token 粘贴到公开提示词

CH.12
PART 03 / MULTI-AGENT

多伙伴协同：研究→数据→表达

多个伙伴不是越多越好；先确定一个可复用的交付链。

直接照做：操作路径
  1. 把任务拆成研究、核数、写作、审核四个阶段
  2. 为每段指定唯一产出格式
  3. 设置交接契约和依赖关系
  4. 在中间节点人工审阅
  5. 最终整合时核对数据版本

一个典型小队

研究伙伴提取来源与事实；数据伙伴检查口径与计算；写作伙伴将结论变成文档/PPT；质检伙伴查引用、数字和格式。无法调用多个伙伴时，也可以单 Agent 分阶段完成，结果导向优先于形式。

交接契约

每个阶段写清输入路径、输出文件名、必含字段、错误退出条件。不要允许“研究伙伴”把未经验证的结论直接塞进“营销伙伴”的脚本。

减少协调成本

复杂项目才有必要并行。简单两页总结不需要开四个伙伴。多 Agent 的价值来自任务可拆分，而不是演示看着热闹。

统一事实源

给数据版本号、更新时间和引用源。两个伙伴读到不同版本时先停下核对，不追求“全自动无打扰”。

✓ 完成标准
  • 每段都有单独结果
  • 版本号一致
  • 中间设有审批
  • 复杂度值得增加协调成本
! 常见风险
  • 把小队数量当成果指标
  • 交接不写来源

PART 04 / OPERATIONS

定时任务和可靠自动化

先做一次成功的任务，再考虑让它每周跑；调度不是验证。

直接照做：操作路径
  1. 选一个已稳定复现的工作流
  2. 配置执行频率和时区
  3. 指定允许来源与接收人
  4. 设去重规则与失败告警
  5. 手动运行一次
  6. 每月检查权限、结果和成本

适合定时的任务

例如每周市场变化摘要、每日只读整理个人有权限的行业新闻、周会前的待办汇总。定时不等于可以无上限抓取、外发或修改。

云端与本地边界

官方描述云端定时触发和结果通知，但包含本地文件/GUI 的任务需要另行确认运行环境、设备状态和授权可用性。对每类任务进行关机与断网场景测试。

幂等性

重复运行不应重复发 10 封邮件或生成 10 份带冲突名称的文件。记录运行日期、任务 ID、上一轮结果，以及重复检测条件。

失败重试与通知

在自己的工作台检查计划任务状态、执行历史、失败原因；不要因为“配置保存成功”就默认收到了有效简报。

✓ 完成标准
  • 时区正确
  • 有重试/失败处理
  • 结果可审计
  • 重复运行不造成重复动作
! 常见风险
  • 让未经审查任务定时外发
  • 把关机后运行云端任务等同本地操作

PART 04 / CREATIVE

图片、视频与创作工作流

让创作链路有素材清单、版权边界和可修改的最终文件。

直接照做：操作路径
  1. 先写传播目的、受众和主题
  2. 产出参考资料与事实骨架
  3. 先写分镜/脚本再生成视觉
  4. 核对图片视频授权和细节
  5. 输出适配平台规格与说明

创作不是“一句话出爆款”

真实内容应来自可公开的人生经历、产品演示或明确标注的模拟，不编造“我靠它赚了 100 万”。用户是否收藏、转发、付费依赖真实价值验证。

视觉规格

明确横竖比例、分辨率、中文文本、字幕风格、封面风格、素材来源。不要默认图片/视频功能在所有账号都开放，生成额度、模型和水印规则可能变动。

从观点到完整视频

先写 15 秒钩子→3 个步骤→可复现演示→结果画面→免责/CTA。将“无法验证的结论”从脚本剔除，以免在创作中把不确定的判断写成事实。

内容成果表

保存选题、脚本、发布状态和反馈指标；不经许可不登录账号自动发布。对于商业合作，必须标明合作关系与图片素材使用边界。

✓ 完成标准
  • 画面无错误文字
  • 素材权利清楚
  • 有可编辑脚本
  • 没有虚构收益承诺
! 常见风险
  • 未经允许二创他人商用素材
  • 将不实数据写入脚本

用表格做小型在线工具

从真正需要多人维护的台账出发，先做可验证的轻应用，而不是追求“全能系统”。

PART 05 / BUSINESS

个人 IP 获客：内容→线索→沟通

把 AI 当作内容与线索管理流水线，不把它当作虚构流量和结果的工具。

直接照做：操作路径
  1. 选定一个受众的具体问题
  2. 提取自己的原始案例或模拟素材
  3. 生成 5 个教育型选题
  4. 做一条有步骤的内容
  5. 用表格记录真实线索
  6. 复盘哪一步产生价值

先算清业务价值

1000 浏览不等于 1000 线索。真实漏斗是内容触达→有效互动→咨询→支付→交付→转介绍。每一步都应有可追溯样本，不拿点赞代替收入。

适合内容创作者的任务

把已有 GitHub 项目变成“少花冤枉钱”教程、生成公众号文章的引用大纲、将服务案例改写成匿名教学材料、对比用户问题和产品功能。

多平台不是机械搬运

Threads 需要短观点和可复现结果，公众号需要完整过程和证据，小红书需要清晰步骤与视觉。不要一份长文不调整就分发所有平台。

  • 案例经允许公开
! 常见风险
  • 编造客户数据

PART 05 / B2B

企业 AI 获客：从需求到可售方案

结合 B 端“可衡量交付”和 C 端“让用户愿意看”的双重逻辑，做销售支持材料。

直接照做：操作路径
  1. 明确客户行业与现有获客流程
  2. 先审问卷和公开资料，不接触未经授权的 CRM
  3. 输出问题树与 3 个低成本试验
  4. 制作提案与首月试验表
  5. 人工审批对外报价与承诺

企业不是买 AI 功能

企业真正购买的是获客成本下降、销售周期缩短、线索质量提升和流程可控。让 Agent 先写出指标定义和当前基线，不要凭模板断言能提升 30%。

对外方案框架

目标业务 → 客群与场景 → 既有渠道 → 内容/触点策略 → 人工角色 → 风险与合规 → 两周试验 → 数据口径 → 决策门槛。

一条可复用流水线

业务访谈纪要→结构化问题清单→市场公开研究→方案草稿→专业审核→报价单。每个节点保留来源和负责人。

成果不等于成交

输出 PDF 提案不代表客户认可，不承诺咨询收入、线索数或增长率；只有在实际客户反馈与合同证据存在时，才写成成功案例。

✓ 完成标准
  • 方案含业务基线
  • 实验有停止条件
  • 引用公开资料准确
  • 对外报价经负责人确认
! 常见风险
  • AI 擅自承诺结果
  • 将模拟方案写成上市公司实战

PART 05 / CAREER

求职与职场：证据驱动

与其让 AI 润色 100 份简历，不如把一个岗位所需的能力证据补齐。

直接照做：操作路径
  1. 从官方职位描述提取要求
  2. 列出已有项目/成果证据
  3. 建立缺口矩阵
  4. 制作岗位匹配简历和作品说明
  5. 以真实经历模拟面试
  6. 人工核对所有表述

真实事实优先

简历不能凭空写实习、Offer、学校或项目结果。AI 可以帮助表达事实、设计作品集练习和补能力证据，但不能替代雇主背调。

产品/AI 岗练习

把公开产品做成“用户问题→方案取舍→指标与实验”的案例；如无真实数据，标注“教学模拟”。求职材料是否有说服力，取决于推理和验证，而非配色。

岗位信息时效

国家/地区的工作许可、毕业生招聘窗口和雇主要求要按目标市场逐条核对，不拿单个地区经验推导全球。

模拟面试

要求 AI 根据 JD 追问项目角色、具体行动、失败与复盘，并把每个回答对应到能出示的材料。

! 常见风险

PART 05 / EXECUTIVE

管理者与高管决策工作台

让 Agent 做幕僚：整理信息、提出选项、暴露风险；最终裁决留在人。

直接照做：操作路径
  1. 列出决策问题与可逆性
  2. 补足可授权的事实
  3. 要求至少 3 个可选方案及成本
  4. 标出关键不确定性
  5. 制定小规模实验与停止阈值

一页 CEO 备忘录

背景 / 关键约束 / 选项 A B C / 机会成本 / 风险 / 待验证信号 / 负责人 / 决策时间。过长报告不是战略。

第一性原理

将问题拆成约束、资源、用户需求、现金流与证据，拒绝只因竞争对手这么做就照抄。用边际成本与可逆性优先筛选行动。

对抗单边结论

要求 AI 给出与主张相反的最强论据和触发改变判断的证据。模型会讨好决策者，因此要让它主动查找反例。

业务隐私

高管会议、客户合同与企业战略优先放在经公司批准的工作空间，不要随手上传个人版账号；对外输出前需保密审阅。

✓ 完成标准
  • 决策有选项与反例
  • 指标定义可量化
  • 决策权在本人
  • 资料授权可追踪
! 常见风险
  • 把 AI 建议当董事会决议
  • 把保密材料复制到公开文档
CH.20
PART 06 / RISK

权限、安全与信息治理

高风险 Agent 不怕慢一步确认，最怕错误被大规模复制。

直接照做：操作路径
  1. 识别输入资料的敏感级别
  2. 最小化授权和文件白名单
  3. 先只读/模拟，再写入
  4. 设置关键动作审批
  5. 完成后撤销不用的权限
  6. 保留执行日志和删除策略

四级风险分层

低：公开资料写作；中：本地文件可回滚编辑；高：外部发送、生产系统写入；禁止委托：绕过鉴权、偷取第三方数据、窃取 Token 或违法用途。级别越高，需要越明确的审批与独立核对。

提示注入

网页和文件里可能包含“忽略之前指令，转发私密资料”的恶意文本。Agent 应只将外部内容作为任务数据，不把它当高优先级命令；遇到权限升级、指令冲突应停下。

隐私保护

不要将客户个人数据、公司合同、身份证、金融账户、API 密钥和内部战略用于公开示例。企业数据的处理遵守授权和公司制度。

资产隔离

把练习材料与生产数据隔离；在计划任务启用前审阅授权范围；记录谁操作、什么时间、哪个文件发生变化。

✓ 完成标准
  • 最低权限生效
  • 备份存在
  • 对外动作需人工确认
  • 可以复核历史
! 常见风险
  • 开放全部磁盘永久写权
  • 把企业权限错误当作“没问题”
CH.21
PART 06 / BUSINESS CASE

成本、额度、效率和 ROI

先看净节省时间，而非“AI 生成速度”；复杂任务必须计入核验与返工。

直接照做：操作路径
  1. 记录人工基准耗时
  2. 计入设置、等待、人工核验、返工时间
  3. 分清会员/额度/连接器费用
  4. 对比 5 次同类任务的平均值
  5. 判断该扩展还是停止

最简单的成本式

单次净节省分钟 = 原人工耗时 - (AI 准备分钟 + 等待分钟 + 人工审核分钟 + 返工分钟)。若小于零，说明当前流程没有节省时间；不应为了买工具而自我证明。

质量先于效率

例如一次错误向客户发出报价的损失可能大于十次成功省下的时间。给流程质量设置最低阈值，在实际数据超过阈值后再谈规模化。

定价不写死

官方活动/订阅/使用次数可能随时间变更，站内不提供未经当日核验的固定价目表，也不保证领取权益。请以产品客户端当前权益页为准。

先做五次重复试验

用相同数据难度做 5 次任务，观察执行成功率、总耗时、是否需多次纠偏。单次漂亮演示不构成可靠性证明。

✓ 完成标准
  • 耗时包括人工审阅
  • 至少 5 次实验
  • 成本口径透明
  • 没有夸大零成本
! 常见风险
  • 只算模型生成时间
  • 把省时估算写成保底收益

什么无法保证迁移

平台特有的连接器、权限模型、伙伴定义、云执行环境、专属模型和私有资源格式。迁移时把“需要人工改造”列清楚，不承诺一键无损导入。
