## 先读这 90 秒：七条最重要的结论

1. WorkBuddy 的核心不是“回答得好”，而是能在授权范围内**操作文件、调用工具、交付结果**。[R1]
2. 新手先使用**默认权限 + 独立工作目录 + 备份副本**，不要把整台电脑交给 Agent。[R2]
3. 简单的明确任务用默认 **Agent**；涉及多步改动先用 **Plan**；探索想法用 **Ask**。[R3]
4. 一句话不是完整任务需求。完整任务至少要包含：**目标、输入、范围、限制、产物、验收、风险、回退**。
5. 本地任务、云端任务、手机远程任务是三种执行环境：**云端不等于能访问你电脑的本地文件**。[R4][R5]
6. 免费体验版有额度和功能边界；**开源的是这套教程、模板和网站，不是腾讯 WorkBuddy 软件**。[R6]
7. 最终交付质量取决于**可核验的事实、结果验收和人工批准**，而不是提示词长度。

**本教程承诺什么**：给你可按步骤复现的动作、输入样例、可复制的指令、验收标准和遇错处理。**不承诺什么**：任何环境都能成功、AI 生成内容绝对正确、自动获得客户与收入、购买套餐后必然回本。

## 01｜认识 WorkBuddy：它到底是什么

WorkBuddy 是腾讯推出的 AI 工作台。它可以理解自然语言、自主规划并执行任务，基于用户授权读取、处理本地文件，并生成文档、表格、PPT、代码等结果。官方将产品定位在日常办公、开发与创意等场景。[R1] 但它不是无需核验的全自动员工，也不是一个万能的文件删除工具。

### 1.1 四个容易混淆的概念

| 概念 | 主要作用 | 应该什么时候用 | 容易犯的错误 |
| --- | --- | --- | --- |
| 聊天模型 | 回答、推理、写草稿 | 问知识、发散想法 | 把“说做了”当成“实际做了” |
| Agent | 读取上下文、调用工具、完成任务 | 有明确可验收的结果 | 不限定目录、不给验收口径 |
| Skill | 沉淀一套重复使用的执行方法 | 同类任务每周要做多次 | 安装来源不明的外部脚本 |
| Connector / MCP | 授权访问外部服务 | 真要跨系统取数或执行 | 授权过度、把客户信息放到不该去的平台 |

官方文档展示了专家、技能、连接器、项目、知识库、远程助理等模块。[R1][R7] 具体功能可用性随客户端版本、套餐、账号和地区变化，先在你的客户端确认入口。

### 1.2 国内版与国际版如何选择

- **国内工作为主**：先去腾讯官方国内入口 `https://www.workbuddy.cn/`，看系统支持、登录方式、模型与套餐。[R8]
- **跨境或国际团队**：另查看 `https://www.workbuddy.ai/` 的国际入口与文档/价格。[R9]
- 不假设两个站点的账号、积分、地区和连接器完全互通；以对应站点实时政策与登录情况为准。
- 本书所有具体菜单操作默认按**2026-11-14 国内官方文档**编写；国际站用户请对照界面执行。

### 1.3 三个判断标准：什么时候值得用

适合：**文件多、步骤多、能明确验收**的任务。例如 30 份会议纪要的整理、150 行销售表清洗、将需求说明变为一个可打开的网页。  
不适合直接全自动放行：付款、删库、发正式合同、处理未经授权的敏感客户信息、以单次输出替代法律医疗财税专业判断。

### 1.4 成功不是“模型说做完了”

把任务写成：**输入可追溯 → 操作可限制 → 输出可打开 → 数据可复算 → 修改可撤销 → 责任可确认**。这是贯穿全书的最小闭环。

## 02｜安装与首次登录：Windows / macOS

### 2.1 安装前检查

1. 从[腾讯 WorkBuddy 官网](https://www.workbuddy.cn/)进入下载页，不从论坛网盘下载未经验证的安装包。
2. Windows：官方文档写明 Windows 10 及以上，x64；ARM64 支持请看当前版本说明，Windows 7/8/8.1 不支持。[R10]
3. Mac：官方文档写明 macOS 12 及以上；M 系列芯片选 **ARM64**，Intel 芯片选 **x64**。[R11]
4. 为测试准备一个全新目录：`WorkBuddy-Lab/`，其中创建 `input/`、`output/`、`backup/`。
5. 将任何真实客户姓名、手机号、合同、账号密码、密钥等从测试目录移走。

### 2.2 Windows 手把手

1. 官网下载 Windows 安装包；确认来源为官方域名。
2. 双击安装，阅读许可条款，选择安装路径，完成安装。[R10]
3. 打开应用并完成页面实际提供的登录方式。不同版次的微信/企业账号入口可能不同。
4. 在新建任务区选择工作空间 `WorkBuddy-Lab`，不要选整个 `C:\` 或整个用户主目录。[R3]
5. 进入权限区，确认显示**默认权限**。在首次任务里不启用完全访问。[R2]

### 2.3 Mac 手把手

1. 苹果菜单 → 关于本机：确认是 **Apple Silicon (M 系列)** 还是 **Intel**。
2. 从官网下载对应 `.dmg`；打开后将 WorkBuddy 拖到 **Applications/应用程序** 文件夹。[R11]
3. 从应用程序目录打开，不要长期直接从磁盘映像运行；按实际系统提示完成登录和必要授权。
4. 创建 `~/Documents/WorkBuddy-Lab` 并设为当前工作空间。
5. 首次只给测试目录权限，建立文件备份；不授予无关系统目录的访问权限。

### 2.4 第一次运行前的“红线检查”

- [ ] 确定当前是本人登录的账号；确认地域、积分和计费页面。
- [ ] 当前工作空间是专用测试文件夹，`input` 为原始文件副本。
- [ ] 权限模式为默认；敏感操作仍须人工确认。[R2]
- [ ] 尚未安装来历不明的 Skill / MCP / CLI；未输入密钥到提示词。
- [ ] 了解哪些文件会出现在输出目录、如何查看“产物”面板。

## 03｜第一个 10 分钟任务：从指令到可验收文件

这章**不需要任何真实业务数据**。先把下面三行文字复制到 `input/meeting.txt`：

```
时间：周一 10:00。主题：下周线索复盘。
决定：小李周三前整理渠道数据，小王周四前整理客户反馈。
风险：数据口径未统一；下次会议：周五 16:00。
```

在 WorkBuddy 里选择 `WorkBuddy-Lab` 工作目录，使用 **默认（Agent）模式**，粘贴指令：

```text
只读取 input/meeting.txt。请把它整理成一份中文会议纪要，包含议题、结论、责任人、截止时间、风险、下一步。
请把结果写入 output/meeting-minutes.md。不得修改 input/ 或其他文件；缺失信息标记“待确认”，不能推测。
完成后请列出实际新建/修改的文件路径，并核对责任人、日期与原始文件逐项一致。
```

**验收动作**：打开 `output/meeting-minutes.md`，逐一检查小李/周三、小王/周四、周五 16:00 是否对应；没有新增不存在的参会人；原始文件没变。文件没生成就算失败，不以聊天回复代替。

### 3.1 三种工作模式究竟怎么选

| 模式 | 官方当前名称 | 适合任务 | 示范 |
| --- | --- | --- | --- |
| 执行 | 默认（Agent） | 范围小、风险低、结果明确 | 整理一份纪要并写入指定文件 |
| 规划 | 计划（Plan） | 涉及多个文件/系统，先看方案 | 把 20 份需求汇总成网站，先看改动列表 |
| 问答 | 仅问答（Ask） | 解释概念、讨论方案，不修改文件 | 介绍如何拆分销售渠道 |

这些名称来自官方当前任务栏文档。[R3] 早期第三方教程可能把执行模式称为 Craft，遇到版本不同请以当前客户端为准。

### 3.2 找不到结果怎么办

先查看右侧“产物/结果”面板，确认工作空间，再在任务里提问：`请只报告已经写入磁盘的文件路径，逐个验证文件存在；不能只贴正文。` 官方支持在结果区查看产物、文件与变更信息。[R1][R3]

## 04｜Andy 的 AI Agent 任务协议：八个不可省的字段

与其背 100 个“神奇提示词”，不如学会把一个工作任务写成协议。以下属于本项目原创可复用方法，不是腾讯官方功能名称。

```text
【目标】一句话说明要解决的真实问题、给谁用。
【输入】只读取哪些文件/网址；数据日期；来源可信度。
【范围】允许做什么，明确禁止做什么。
【约束】受众、语言、预算、格式、截止时间、质量口径。
【产物】文件类型、命名、保存路径，以及复现说明。
【验收】必须逐项通过的测试；不确定必须标“待核实”。
【风险】隐私、删除、联网、公开发布、付费、外部通知。
【回退】先备份，出错时保留旧版并说明恢复方法。
```

### 4.1 一个好任务 vs 一个坏任务

坏：`帮我优化公司的客户数据并自动发给团队。`  
好：`只读 input/customers-demo.csv；先检查重复与缺失值，输出 cleaned.csv + report.md；不回写源数据、不联网、不发送任何消息；把变动数、异常行号列出来；人工审核后才允许下一步。`

### 4.2 第一性原理：拆到不能再拆

将任务切成 **来源（事实）→ 变换（规则）→ 产物（格式）→ 验证（证据）**。在每一步问：如果 AI 出错，哪一项信息可以独立复算？如果不能复算，至少要留下审阅清单。避免因流程自动化而放大错误。

### 4.3 五步工作法：把流程做得更轻

1. **质疑需求**：这个报表、这页 PPT 真的需要吗？
2. **删掉冗余**：删去不为验收服务的字段与中间步骤。
3. **简化优化**：让输出尽量是一份结构化、可机器检查的文件。
4. **加速反馈**：先拿 3 条数据试跑，而不是 3 万条。
5. **适度自动化**：稳定通过验收后，再考虑重复执行、对接外部系统。

顺序不能倒过来：错误流程上加自动化，通常只会更快地批量犯错。

## 05｜办公四件套：Word、Excel、PPT、PDF 的真实场景

### 5.1 周报从“流水账”变成可核验的结果

输入：`input/weekly-notes.md`（5—12 条工作事实）。输出：`output/weekly-report.md`（或使用已验证工具生成 `.docx`）。先按“目标—动作—产物—问题—下周实验”汇总；所有数值必须可追溯到源材料。**不编造完成率和增长率**。

### 5.2 Excel 销售数据：先做口径，再做图

输入：`examples/sales-demo.csv`。先说明一行是什么（订单还是客户）、金额单位、去重键、退款是否计入，再按渠道统计金额与订单数。示例使用虚构数据，仅用于练习；导出的报表必须与 CSV 公式复算一致。

### 5.3 PPT 汇报：先结论，再证据

让 Agent 先生成**8 页以内讲稿大纲**：第一页决策，第二页问题，第三至五页证据，第六页选项，第七页建议，第八页行动计划。未经批准不借用真人证言、虚构项目进展或“公司增长 300%”。再生成 PPT，并人工检查文字溢出、页码与来源。工具是否支持可编辑 PPTX，以你安装的客户端/技能为准。

### 5.4 PDF：交付质量的最后一公里

最终 PDF 逐项核验：中文字体可搜索、超链接可点击、页面没有溢出、二维码/联系方式真实、图片有来源、手机阅读排版合理。**不要为了看起来精美而牺牲可复制性和信息准确性**。

### 5.5 批量文件整理：永远先 dry-run

Agent 先只生成“旧路径 → 新路径 → 重名风险 → 需人工判断”预览表；明确 `不得删除或覆盖文件`。审阅后再在备份副本上执行；导出文件变更日志；抽检至少 5 个文件。

## 06｜数据分析：以一次能复算的 CSV 为例

本仓库 `examples/sales-demo.csv` 共 8 行、4 个字段：日期、渠道、订单号、金额（元），为教学模拟数据。尝试以下指令：

```text
读取 examples/sales-demo.csv。先报告文件行数、列名、金额单位、空值和重复订单号。
按渠道汇总订单数与金额，输出 output/sales-summary.csv 和 output/sales-audit.md。
生成的渠道金额之和必须等于非重复原始记录金额之和；列出复算公式与数据范围。
对异常值先标记，不要私自删行。禁止联网上传、禁止修改源文件。完成后逐一验证产物。
```

### 6.1 四种常见数据陷阱

- **分母错**：把订单转化率写成付款人数 / 浏览次数，却混了不同时段。
- **重复算**：同一个订单在导出时出现多次，没有明确去重键。
- **把相关说成因果**：销售增长和发帖同步发生，不代表发帖导致销售增长。
- **精确得离谱**：样本不足时给出小数点后两位的“转化提升”，没有不确定性说明。

### 6.2 业务判断的底线

任何业务结论都包含三段：**我们观察到了什么（事实）→ 可能为什么（假设）→ 如何用一次小实验验证（动作）**。输出必须把这三段分开。

## 07｜内容创作者：从选题到发布前 QA

这里使用 AI 酋长 Andy 日常关注的**冷知识、职业成长、AI 生产力**内容类型做教学工作流。以下是方法示例，不是声称这些样例已在 WorkBuddy 上真实跑出流量。

### 7.1 找到“普通人看完就能做”的选题

输入：一批自己有权使用的评论/痛点文本或公开平台链接。先筛“目标用户明确”“痛点发生频繁”“30 秒讲清结果”“可以公开验证”的主题，再排序。不要把他人付费课程批量复制到你的账号，也不要编造产品免费权益。

### 7.2 一篇文章生产三种版本

1. **事实底稿**：带来源链接、时间与限制，一次校准事实。
2. **X/Threads 短稿**：钩子不是空喊“震惊”，而是让人看到成本差异或实际结果。
3. **公众号长稿**：加入背景、完整步骤、失败场景与 FAQ。

分别输出草稿，不允许未经审核直接发布；不同平台对应不同字数和排版限制，发稿前确认最新平台规则。

### 7.3 一份 90 秒视频脚本

让 WorkBuddy 输出 `shot-list.csv`：镜头编号、画面说明、口播、屏幕动作、证据素材、时长。重点是用户能照着**录屏/拍摄**，不是堆积无法实现的 AI 特效。任何演示必须标注真实界面还是教学模拟。

### 7.4 内容审核“四重门”

事实：有来源吗？  合规：侵犯隐私或版权吗？  可用：观众能照做吗？  商业：不看广告也能获取完整答案吗？

## 08｜求职者：不要只让 AI 美化简历

好的求职 Agent 目标不是“简历变漂亮”，而是**把岗位需要的能力，与候选人真正做过的事匹配起来**。

### 8.1 岗位证据矩阵

把 **JD 原文** 与 **自己确认真实的经历**放进专用目录，先输出 `requirement-evidence.csv`：岗位要求、证据出处、证据强度、缺口、下一个行动。没有经历必须标记“待补充”，不能由模型代写成已做成的项目。

### 8.2 求职材料四件套

岗位分析 1 页、证据矩阵 1 份、针对性简历 1 份、模拟面试题库 1 份。对留学生岗位还须核验当地招聘窗口、工作资格、签证/工签规定，不套用单一国家规则。

### 8.3 模拟面试与复盘

让 AI 以面试官身份围绕“目标、约束、行动、取舍、结果、复盘”追问；评分依据岗位 JD 预先约定，不要把 AI 的评分当雇主评价。面试后记录容易被追问的证据缺口并补材料。

## 09｜创业者 / 小企业：从操作人员升级为验收负责人

下面是**教学模拟**，不构成用户真实业务业绩或对 WorkBuddy 的已完成实测。

### 9.1 企业 AI 获客：先定义“线索”，再看流量

公司不要先提“AI 每天帮我发 100 篇文章”。先明确：目标客户是谁、一次有效线索如何定义、数据从哪里来、由谁跟进、关闭循环的成本是多少。WorkBuddy 可以帮你在有授权数据的前提下整理漏斗，**但不能替代真实渠道归因与获客实测**。

### 9.2 销售线索分级

给 20 行匿名模拟线索表，设置评分：预算已确认、需求明确、决策角色、下次联系时间。先公开评分规则，再按规则分级；人工复核重要客户和特殊情况。未经授权不得从私有客户聊天记录自动采集资料、发送营销信息。

### 9.3 企业知识库：解决新人反复问同一问题

选择一批经授权的产品 FAQ/售后 SOP/公开服务材料，建立来源清单、版本号、责任人。问题输出必须标“引用自哪份文档、什么日期、还存在什么不确定性”；过期价格和合同口径不得自动沿用。

### 9.4 用一次 2 周实验验证价值

**假设**：如果整理线索变快，销售能够把更多时间用于有效跟进。  
**实验**：同类线索分别使用/不使用 Agent 辅助整理，记录人工处理时长、错误率、跟进完成率。  
**边界**：不因一次观察就断言工具导致成交增长。采用边际成本和真实反馈决定是否扩大。

## 10｜普通人做网站：从一个页面开始，而不是一口气开发 SaaS

### 10.1 最小需求包

目标用户一句话、用户在页面完成的动作、必须保留的字段、界面参考、数据隐私规则、验收列表。先做**完全离线可打开的静态网页**，不需要数据库、不需要 API Key、不需要注册。示范任务：个人联系卡或匿名销售统计页面。

### 10.2 给 WorkBuddy 的任务

```text
在当前工作空间新建 demo-site/，只生成 index.html、style.css、app.js、README.md。
制作一个无需注册的“每周工作计划”静态网页：添加任务、完成勾选、按优先级筛选、导出 JSON。
数据默认只保存在浏览器本地，不接第三方统计，不要求 API Key。请先列出文件结构与验收清单。
不得修改工作空间以外文件。完成后用可用工具检查 HTML 语义、键盘访问、手机视口无横向滚动。
给出不超过 10 条的手工测试步骤；无法执行的检查标记“未验证”，不得报通过。
```

### 10.3 发布 GitHub Pages，确认每一步

1. 用本地浏览器跑通操作与导出，录下失败问题。
2. 在**本人 GitHub 账号**创建公开仓库，上传源码和 LICENSE、README。
3. GitHub 仓库设置 → Pages → 选择合适的分支/目录或 Actions 发布；具体入口可能随 GitHub UI 变化。
4. 等构建成功后，**实际打开网站 URL**，在手机/桌面核对路径、资源与交互；GitHub 提交成功不等于 Pages 已成功上线。
5. 不在公开仓库放 token、客户原始数据或不获授权的素材。

## 11｜Skill / 连接器 / 远程助理：先设边界，再加能力

### 11.1 你什么时候需要做 Skill

如果同一个任务至少重复做 3 次，每次步骤基本相同、可验收标准稳定，才值得提炼成 Skill。它应描述**输入、步骤、输出、异常、权限、安全、验收**，而不是写一个模糊的“你是全能专家”。

### 11.2 自建 Skill 的最小结构

本仓库 `skills/andy-task-qa/SKILL.md` 是**可编辑示例**，核心是对任务产物做 QA，不是一个声称已在所有 WorkBuddy 客户端验证的安装包。官方支持在技能管理界面上传/创建技能，第三方技能可能调用脚本或外部服务，务必先检查权限与来源。[R12]

### 11.3 连接器和 MCP 先做只读测试

连接器能在获得授权后访问外部服务，也可能向第三方发送信息。[R7] 第一次连接先执行**只读查询**，确认范围、信息敏感级别、授权撤销入口和审计记录。邮件发送、客户通知、修改云端文档等属于**更高风险动作**，必须在发送前明确逐项批准。

### 11.4 手机遥控电脑，不等于远程无条件执行

官方远程助理支持通过微信、企业微信、QQ 等渠道给电脑上的 WorkBuddy 派任务；实际支持渠道以客户端入口为准。[R5] 本地任务需要电脑客户端可用、授权有效；云端任务无法直接读取本机文件。首次远程仅测试“查询进度/读取测试文本”，不要直接用于发客户邮件、改账本、付款。

### 11.5 记忆与资料库的正确用法

整理可公开的 SOP、品牌资料、模板与规则时优先注明版本、有效期、出处。个人身份、客户隐私、密钥等不应作为开放资料库的一部分；允许云端接入前先看隐私条款、企业数据协议、存储/地域和管理员权限。[R13]

## 12｜交付验收：六个关键质量检查

| 检查门 | 最低合格标准 | 一旦失败怎么办 |
| --- | --- | --- |
| 事实 | 数字/人名/日期有文件行或官方链接 | 回到源材料重算 |
| 完整 | 输出文件存在、能打开、目录清晰 | 请求指定路径重新生成 |
| 安全 | 不越权、不包含客户敏感数据 | 停止发布并人工脱敏 |
| 一致 | 多种格式的同一指标口径一致 | 生成差异表并修正 |
| 复现 | 别人用同样的示例可得相近产物 | 补齐输入与版本说明 |
| 可撤销 | 源文件保留、变更有日志和备份 | 回滚副本重试 |

### 12.1 永远让 Agent 给证据，而非只给结论

通用验收补充指令：`请用表格列出每项验收标准、实际证据/文件路径、检查方法、结果（通过/失败/未验证）、剩余风险。未调用工具验证的项目不能标“通过”。`

### 12.2 高风险操作必须保持人在环

涉及资金、外部发布、客户通知、员工人事、法律财税、删除、权限变化，不能让定时任务自动做最终授权。执行前暂停，展示具体影响范围和待确认清单。官方也明确提醒无人值守任务应慎重配置文件删除、资金操作。[R4]

## 13｜定时任务与成本：别让“省时间”变成无限消耗

官方定时任务分本地、项目、云端三种来源。本地任务在本机客户端执行，电脑关闭或退出客户端可能中断；云端任务在云端沙箱中执行，不依赖电脑在线，**但不能访问本机文件**。[R4]

### 13.1 从一条最安全的自动化开始

新建任务：每天 18:00 根据**云端可访问的公开页面或预置文本**写一段摘要；不得发送给别人，不得更新外部系统，只保存摘要。**先手动运行一次，看输出和积分，再开启定时**。[R4]

### 13.2 真要处理本机文件

明确选择**本地**执行、设置专用工作空间、确认电脑运行条件；只读扫描和新建输出文件可自动执行。删除、覆盖、外发前需人工确认。不要在无人值守场景随意开启完全访问。

### 13.3 WorkBuddy 花费怎么算

**不要用“免费无限用”宣传。** 官方国内定价文档在 2026-11-14 显示体验版免费，付费分标准/高级/旗舰，存在积分、模型和自动任务配额差异及限时优惠。[R6] 例如文档列出标准版 99 元/月标价与体验版每月基础积分 500（优惠口径可变），购买时应以页面实付为准。[R6] 海外版是另一套美元计费说明，请单独核对。[R9]

用一张成本表记录：`任务｜耗时（人工）｜耗时（AI+人工复核）｜积分消耗｜输出是否合格｜失败次数｜额外成本`。月度净价值≈节省的人工时间价值－订阅/积分/复核返工与风险成本。人均时薪、成功率和节省时间必须自己实测，不能套用营销口径。

## 14｜最常见的 12 个坑，以及最快修复路径

| 现象 | 常见原因 | 优先操作 |
| --- | --- | --- |
| 说完成但没有文件 | 只输出了聊天内容 | 检查“产物”和真实路径 |
| 找不到源文件 | 当前工作空间错误 | 指定准确目录/相对路径 |
| 原文件被覆盖 | 没要求保留源文件 | 先复制到 `input/`，启用备份 |
| 内容数字不一致 | 表格口径或重复记录 | 先定义去重键与公式 |
| PPT 漂亮但讲不通 | 没有先锁定叙事结构 | 先审大纲再做设计 |
| 程序能打开但按钮没反应 | 没跑交互测试 | 浏览器逐项测试 |
| 自动任务错过时间 | 本地电脑断电/退出 | 核对执行来源和运行记录 |
| 云端任务看不到电脑文件 | 执行环境不同 | 在本地任务执行或显式上传已授权材料 |
| 发送信息被中断 | 默认权限等待确认 | 审查风险后人工确认，而非直接全权授权 |
| 技能安装后出奇怪权限请求 | 第三方脚本与配置 | 停止、审源、检查权限 |
| 积分消耗超预期 | 任务过大/重试循环 | 缩小输入和输出、先抽样、看用量 |
| 不知道为什么失败 | 没有日志 | 保留提示词、截图、版本、错误和产物路径 |

## 15｜摆脱单一平台依赖：任务协议与资产应该属于你

不要把全部方法锁在某个产品。**WorkBuddy、ChatGPT、Gemini、Codex 等工具的交互和权限各有差异**，但好的任务通常有可迁移的共同结构：输入资料、任务定义、输出规范、质量门槛、版本控制。

建议每个复用流程都保留这些**厂商无关**资产：

```text
my-workflow/
├── README.md            # 谁使用、何时使用、有什么限制
├── task.md              # 八字段任务协议
├── input-schema.md      # 字段和来源说明
├── sample-input.csv     # 匿名/教学数据
├── acceptance.md        # 结果验收清单
├── changelog.md         # 修改历史
└── outputs/             # 本次实际产物，不含客户隐私
```

### 15.1 从聊天记录走向工程资产

聊天记录可以留痕，但不要只保存聊天记录。最终产物应是独立的 Markdown、CSV、HTML、PDF 或可编辑文档。把“输入/输出/检查”放进 GitHub 项目，任何支持本地文件的 Agent 都可以沿同一套验收标准工作。

### 15.2 遇到模型切换或套餐变化

换模型时先做**回归样例**：同样的 3 个输入，观察事实错误、格式、权限提示、产物质量、实际成本是否变化。保持开源模板可复现，才能降低供应商锁定。

## 16｜七天训练营：从第一个文件到独立工作流

| 天数 | 任务 | 可以验收的结果 |
| --- | --- | --- |
| Day 1 | 安装 + 权限设置 + 纪要整理 | 原文件不变、结果存在 |
| Day 2 | CSV 分析与公式复核 | 数值与原始数据一致 |
| Day 3 | 周报与 PPT 大纲 | 事实出处完整 |
| Day 4 | 内容选题与多平台文案 | 无虚构权益与事实 |
| Day 5 | 创建自己的工作 QA Skill | 示例说明可读、输入输出定义清楚 |
| Day 6 | 实验性定时任务 | 运行记录可追踪、风险可控 |
| Day 7 | 打包到 GitHub | 有 README、模板、回退与许可证 |

**进阶 30 天**：第 2 周把 1 个工作流稳定到可复现，第 3 周收集 10 次执行日志、定位最耗时步骤，第 4 周在不牺牲安全与正确性的前提下做小范围团队使用。不要把“装了多少 Skill”当成绩，应当衡量合格交付量与返工率。

## 18｜FAQ：必须说清楚的边界

**Q：本项目是不是腾讯官方教程？**  
A：不是。这是 AI 酋长 Andy 独立编写的公开教程，与腾讯没有从属、赞助或认证关系。

**Q：WorkBuddy 是完全开源软件吗？**  
A：本项目只开源教程、模板、示例数据、网站源代码。WorkBuddy 产品本身的许可和服务以腾讯官方为准。

**Q：不买会员能做完本教程吗？**  
A：基础练习优先用免费额度完成，但额度、可选模型、积分耗用随版本而变。没有任何“无限免费”保证。[R6]

**Q：把客户资料放进去安全吗？**  
A：先审数据分类、客户授权、平台隐私条款、连接器和模型数据流向；学习阶段只使用匿名或模拟数据，不接受“AI 天然安全”的假设。[R2][R7]

**Q：在手机上能控制电脑吗？**  
A：官方有远程助理和微信小程序的对应操作模式，但手机与电脑绑定、电脑在线/授权、云端/本地区分都需要检查。[R5][R14]

**Q：能定时执行吗？**  
A：支持，但本地任务和云端任务的执行条件不同。前者可能因电脑离线中断；后者不能访问本机文件。[R4]

**Q：可以直接靠 WorkBuddy 自动赚钱吗？**  
A：不能把工具能力等同商业结果。要验证目标客户需求、付费意愿、获客成本、交付质量和边际利润。

**Q：和 ChatGPT / Codex / Gemini 怎么选？**  
A：看任务是否需要本地文件操作、外部连接器、代码执行、审核与跨平台输出。不要只看模型榜单；用同一个真实任务和验收标准横向试跑。

**Q：UI 跟本书截图或描述不一致怎么办？**  
A：优先使用[官方帮助中心](https://www.codebuddy.cn/docs/workbuddy/Overview)和应用当前文字入口；本书更新记录会同步维护。

**Q：如何贡献新的任务示例？**  
A：提交 PR，包含最小输入、提示词、预期输出、人工验收结果、运行环境、参考文档日期；不得提交真实客户隐私与未经授权的商业数据。
