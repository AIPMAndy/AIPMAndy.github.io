# Andy Task QA（教学 Skill 模板）

## 使用时机
当用户要求检查由 WorkBuddy 或其他 Agent 生成的文档、数据汇总、网页或代码变更的可靠性时触发。此示例以 Markdown 描述方法；**未声明已在全部 WorkBuddy 版本中实测安装**。

## 必须收集的输入
1. 产物的实际文件路径；2. 原始输入及其授权范围；3. 任务协议；4. 用户要求的验收标准。

## 强制流程
1. 首先列出工作目录和需要读取的文件；缺少信息时暂停，不猜路径。
2. 默认只读。不运行第三方脚本、不联网、不删除文件、不修改项目。
3. 对文档核对事实、出处、标题结构与链接；对 CSV 检查行数/列名/去重键/聚合复算；对网页检查静态资源路径与关键交互（仅在有安全、受控的测试环境时）。
4. 对所有声称“通过”的项目，必须有真实证据，不能仅凭模型推断。
5. 输出审查报告 `output/task-qa-report.md`，表头为 检查项 | 标准 | 证据 | 结果 | 修复建议。结果只允许“通过 / 失败 / 未验证”。
6. 若发现越权、敏感数据、危险代码或外传风险，立刻标记“需人工处理”，不可自行提交/上传/发送。

## 输出与终止条件
任务完成条件：报告存在、所列证据可回溯、未验证项未冒充成功、源文件无修改。

## 禁止事项
- 不能用“感觉不错”替代验收；不能编造性能得分或客户效果。
- 不能直接接收秘密 Token、生产账号密码、个人证件。
- 不能假装通过浏览器/文件系统检查而没有工具日志。
